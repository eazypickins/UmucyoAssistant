# Chapter 15

# Engineering Blueprint (Part II)

## Objective

This chapter defines the technical architecture required to build UmucyoAssistant as an enterprise-grade, AI-powered Procurement Intelligence Platform.

The emphasis is on scalability, maintainability, explainability, and modular growth.

The architecture should allow new AI agents, datasets, workflows, and integrations to be added with minimal disruption.

# BigQuery Intelligence Warehouse

Maintain analytical data separately from transactional data.

Suggested datasets include:

Historical Tenders

Award History

Supplier Participation

Buyer Profiles

Category Performance

Regional Procurement Trends

Contract Values

Sector Analysis

Tender Timelines

Historical Evaluation Patterns (where publicly available)

This separation ensures analytical workloads do not impact operational performance.

---

# AI Orchestrator

Every AI request should pass through an orchestration layer.

Responsibilities:

Determine the user's intent.

Select the appropriate AI agent.

Retrieve contextual information.

Retrieve relevant knowledge.

Execute BigQuery analysis if required.

Generate response.

Log interaction.

Collect feedback.

This avoids duplicating logic across multiple AI agents.

---

# Retrieval-Augmented Generation (RAG)

Every AI response should be grounded in authoritative context.

Potential sources include:

* Public procurement regulations.
* Umucyo training materials (where licensing permits).
* Academy content.
* Internal knowledge articles.
* Historical procurement insights.
* Customer-specific documents (private).
* Proposal templates.
* Frequently asked questions.

Responses should clearly distinguish between:

* Historical evidence.
* Current user data.
* AI recommendations.

This improves transparency and user trust.

# Event-Driven Workflows

Rather than relying only on scheduled jobs, important business events should trigger automated actions.

Examples:

New matching tender published

↓

Calculate Opportunity Score™

↓

Notify customer

↓

Recommend Academy lesson if readiness is low

↓

Create dashboard notification

↓

Schedule reminder before submission deadline

Other events include:

Proposal uploaded.

Certificate nearing expiration.

Academy course completed.

Subscription renewed.

Workshop registration.

Proposal review finished.

# Security Model

Security should follow the principle of least privilege.

Requirements:

Role-based access control.

Organization isolation (multi-tenancy).

Encrypted document storage.

Encrypted secrets.

Audit logging.

Secure API authentication.

Session management.

Regular backups.

Input validation.

Rate limiting.

Where AI responses use customer documents, ensure they remain isolated to that customer's workspace unless explicit permission is granted.

---

# Audit & Explainability

Every AI-assisted decision should be traceable.

Record:

Prompt used.

Knowledge sources consulted.

BigQuery queries executed.

Confidence indicators (where meaningful).

User feedback.

Timestamp.

This enables continuous improvement and supports troubleshooting.

# Engineering Principle

Every new feature should answer at least one question:

Does it help customers make better procurement decisions?

If not, reconsider whether it belongs in the platform.

Engineering effort should always reinforce the mission of improving procurement capability.
